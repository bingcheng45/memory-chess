# Forty-five boards: first-visit intro

Prototype: `d2-intro.html` in the Blindfold Home Concepts artifact (https://claude.ai/artifact/AYRWxVrVyfu8kGnowpi34J). It is throwaway; this plan is the real build.

## What the visitor gets

A first-time visitor to the home page sees a 10-second intro over the page, then it fades into the home page as it is today.

1. One board, Morphy's Opera Game (Paris, 1858) playing move by move. "One board. You can see it."
2. The camera pulls back as 44 more boards appear, every one a game in progress. "Now forty-five." São Paulo, January 1947.
3. Every board goes dark from the centre out. "He saw none of them." About 23 hours, 39 wins.
4. The camera pushes into one board. "Start with one." The layer fades and the home page is there.

It plays by itself. Nobody has to scroll. Skip shows from the first frame. Esc skips. Tap, Enter, an arrow key or a scroll jumps to the next beat, so a visitor who wants to move on can. It plays once per browser. A "45-board intro" chip on the home page replays it for anyone who wants to see the story again.

Search visitors and crawlers see it too (both decided 24 October 2026). The home page's HTML, title, H1, canonical and structured data do not change for anyone.

## Decisions taken

| Question | Decision | Why |
|---|---|---|
| Bots at runtime or recorded games | Neither at runtime. A build script plays the games with chess.js and commits the result as square changes per ply. | The repo already keeps chess.js out of the client bundle (`scripts/generate-showcase-reach.mjs`). Measured: 45 full games are 12.5 KB gzipped as PGN, and a bot move costs about 3 ms in Node with chess.js 1.x, which is worth paying once at build, not 30 times a second on a phone. |
| Centre board | Replays the Opera Game | The one board people can read should be real master play. Checked in chess.js: legal, ends in mate on move 17. |
| Other 44 boards | 14 real openings, then a one-ply greedy bot, generated with a fixed seed | Legal, varied, deterministic, so a test can pin them. |
| Timed or scroll-driven | Auto-play on a timeline, 10 seconds (decided 25 October 2026). The prototype's scroll-driven mode is not built. | The reveal depends on pacing, which a timeline controls exactly. A first-time visitor needs no instruction. It ends by itself and does not take over the page's scroll. |
| Scroll during the intro | Jumps to the next beat, the same as a tap | A scroll is a natural sign of wanting to move on. |
| Who sees it | First visit only, gated by the rule table below | One table, first match wins, each rule one line and one test. |
| Crawlers | No crawler rule. Googlebot gets the same page and intro as a first-time visitor. | A rule that hides the overlay only from Googlebot is the kind of difference Google's cloaking guidance is about. The page text is in the HTML either way. Link-preview bots run no JavaScript, so the shell stays hidden for them. Cost: Google's rendered snapshot shows the intro's first frame. |

## Who sees it

The gate runs before first paint in an inline script, the same pattern as `RECORD_HINT` in `src/components/home/recordHint.ts`. It marks its own `<script>` element, because the root `<html>` in `src/app/[locale]/layout.tsx` has no `suppressHydrationWarning`, so an attribute on it would break hydration.

| Rule | Result |
|---|---|
| Feature flag off (`NEXT_PUBLIC_HOME_INTRO !== "1"`) | No intro |
| `prefers-reduced-motion: reduce` | No intro |
| `navigator.connection.saveData` | No intro |
| Seen flag in local storage | No intro, replay chip |
| URL has a `#section` | No intro |
| Anyone else | Intro |

Removed from the prototype: the search-landing rule and the crawler rule. Googlebot renders what a first-time visitor sees, so nothing differs by user agent, and Lighthouse measures the intro's real cost.

## Shape of the code

| Piece | File | Notes |
|---|---|---|
| Game data | `scripts/generate-simul-games.mjs` writes `src/lib/home/intro/simulGames.ts` | Header "Generated by … Do not edit", `--check` mode like the showcase generator. Per board: the opening name, the starting placement and one change list per ply (`[square, piece or empty]`), so castling, en passant and promotion are already resolved. About 30 plies per board, enough for 10 seconds. |
| Opening book and seed | `src/lib/home/intro/simulSource.ts` | The 14 lines and the Opera Game as SAN, read by the generator. |
| Gate | `src/lib/home/intro/introGate.ts` | `INTRO_RULES` table, `decideIntro(signals)` (pure), and `INTRO_GATE` (the inline script string built from the same table). Seen key in `src/lib/lab/storage.ts` beside `SUMMARY_KEY`. |
| Timeline | `src/lib/home/intro/introBeats.ts` | The beats table (`one`, `many`, `dark`, `you`, `end` with start times) and the camera as pure functions of time, so tests can ask "what is on screen at 6.2 s". |
| Shell | `src/components/home/intro/IntroShell.tsx` | Server rendered. Fixed black layer, first caption and Skip, hidden by CSS unless the gate marked its script (`script[data-home-intro] ~ .home-intro`). A CSS-only failsafe hides it after 12 s, so a failed script can never leave the page black. `body:has(script[data-home-intro])` stops page scroll while it plays. |
| Player | `src/components/home/intro/FortyFiveIntro.tsx` | Client, loaded with `next/dynamic` only when the gate passed, so other visitors download none of it. Canvas, cached board bitmaps, device pixel ratio capped at 2, pauses when the tab is hidden, stops for good at the end. |
| Replay chip | `src/components/home/intro/IntroReplay.tsx` | Small fixed button. Clears nothing, just plays again. |
| Mount | `src/app/[locale]/(home)/page.tsx` | Adds the gate script and the shell next to `BrainLabHome`, which does not change. |
| Copy | `messages/*.json` under `home.lab.intro` | Reaches the client through the home layout's existing `home.lab` scope. 23 locales, checked by `npm run validate:messages`. |
| Analytics | `src/lib/analytics/events.ts` | New `FunnelEvent` members: `home_intro_shown`, `home_intro_skipped` with the beat, `home_intro_completed`, `home_intro_replayed`. GA4 only, not mirrored to Databuddy. |

## Build order

Each step ends in a check, and each is its own PR into `main`.

1. **Game data.** The generator, the source lines and the committed `simulGames.ts`.
   Check: a test replays every board's change lists and compares each ply with chess.js boards rebuilt from the SAN (literal FENs at a few plies). `--check` passes in CI.
2. **Gate and shell, behind the flag.** `introGate.ts`, `IntroShell.tsx`, the mount, a still first frame and Skip.
   Check: `decideIntro` returns the expected rule for each row of the table. The SSR test confirms the home HTML only gains the hidden shell and the script. The verify-memory-chess skill drives a first visit, a second visit, reduced motion and a `#faq` link.
3. **The player.** `introBeats.ts`, `FortyFiveIntro.tsx`, `IntroReplay.tsx`, English copy.
   Check: the beats test asserts the caption and board count at fixed times. Drive the real app at 375 by 812 and 1440 by 900 and record both. Measure script time per frame in the real app.
4. **Translations and analytics.** 22 more locales and the four events.
   Check: `validate:messages`, and the events showing in GA4 DebugView.
5. **Launch.** Turn the flag on for a Vercel preview, then production.
   Check: Lighthouse on the preview with the intro on and off (mobile and desktop), compare LCP, CLS and TBT. Then watch Search Console and the GA4 numbers for two weeks.

## Open decisions

1. **Intrusive interstitial signal.** Showing the intro to search visitors on mobile carries some risk under Google's interstitial guidance. It is kept small by the Skip button from frame one, the 10-second self-ending, and once per browser. Search Console impressions and the home page's position for "memory chess game" are the numbers to watch after launch. If they drop, the fix is one gate rule.
2. **Copy in 22 locales.** Machine translation, not read by native speakers, the same as the trust pages. Fine to ship that way, or hold for review?

## Not in scope

The other four concepts, any change to the home page content, and the Learn history pages.
